# DMAPRIME-QR_E

This repository contains the weekly Flu MetroCast submission pipeline for the `DMAPRIME-QR_E` model. The model produces a 4-week forecast for U.S. influenza locations using a median ensemble of three quantile models: gradient-boosted quantile regression (GBQR), quantile random forest (QRF), and linear quantile regression (LQR). For South Carolina, North Carolina, and Georgia, the submission is adjusted with a pooled Prisma Health + MUSC correction when the local signal is sufficiently complete and current.

## Model summary

The forecast is generated by combining the outputs of three component models trained jointly across MetroCast locations and auxiliary NSSP series. The final model output is the median of the three model quantiles, with no interval widening.

For South Carolina, North Carolina, and Georgia, the median-only forecast may be replaced by a state-specific correction based on the pooled Prisma Health and MUSC surveillance signal. The correction is applied only when the underlying data pass freshness and completeness checks; otherwise the code falls back to the uncorrected median forecast.

- `run_weekly.R` — main weekly pipeline

- `config.R` — local configuration values
- `metrocast_lib.R` — helper functions for training, prediction, and output formatting
- `correction.R` — Prisma + MUSC correction logic

- `model-metadata/DMAPRIME-QR_E.yml` — model metadata for the hub
- `tests/` — validation and safety checks

## Weekly procedure

The pipeline is intended to be run once per week after the FluSight hub data update becomes available.

### 1. Configure the local setup

Edit `config.R` once to set the local paths and model identifiers:

```r
CONFIG <- list(
  hub = "flu-metrocast",
  data = "data",
  prisma = "/path/to/Prisma_Health_Weekly_Influenza_State_dx_...csv",
  musc = "/path/to/MUSC_Weekly_Influenza_State_dx_cond_lab_Incident.csv",
  team = "DMAPRIME",
  model = "QR_E",
  threads = 4L
)
```

`hub` is the local clone of `reichlab/flu-metrocast`, `data` is the working directory for downloaded data and generated outputs, and `prisma`/`musc` point to the local weekly health-system files used for the correction step.

### 2. Run the forecast

From the repository root:

```bash
Rscript run_weekly.R --update
```

This runs the full weekly workflow defined in `run_weekly.R`:

1. Creates the `data/` directory if needed.
2. Updates the hub clone and downloads the latest NSSP parquet data when `--update` is used.
3. Reads the hub `tasks.json` and identifies the active round for the target Saturday.
4. Loads the latest hub data and auxiliary NSSP series.
5. Builds the feature panel and training rows for the season.
6. Fits GBQR, QRF, and linear quantile regression.
7. Predicts the target week and combines model output by the median.
8. Applies the Prisma + MUSC correction for SC, NC, and GA when eligible.
9. Converts quantiles into a valid submission sample format.
10. Writes the parquet submission file.
11. Runs validation checks.
12. Generates plots and diagnostics.

Alternatively, from RStudio, source `run_from_R.R` to launch the same pipeline with a single click.

### 3. Reference date handling

By default, the script selects the upcoming Saturday as the reference date. This is the date used to determine which hub round is active and which target week is being forecast. A custom date can be supplied with:

```bash
Rscript run_weekly.R --reference-date 2026-10-24
```

### 4. Output files

The script writes a submission file in the hub model-output directory:

```text
flu-metrocast/model-output/DMAPRIME-QR/<reference-date>-DMAPRIME-QR_E.parquet
```

It also writes diagnostics and plots to the local `data/` directory:

- `data/plots/<reference-date>-DMAPRIME-QR_E.pdf`
- `data/plots/<reference-date>-DMAPRIME-QR_E.html`
- `data/diagnostics/<reference-date>-DMAPRIME-QR_E_quantiles.csv`
- `data/diagnostics/<reference-date>-DMAPRIME-QR_E_internal.rds`

## Validation and submission

After writing the forecast file, the pipeline runs the repository's validation rules before completing. If validation passes, the script reports the number of checks passed. If a check fails, the workflow stops and the file should not be submitted.

The final output is intended to be committed to the model-output directory of a fork of `reichlab/flu-metrocast` and submitted via a pull request.

## Correction safety checks

The correction logic is intentionally conservative. The pooled Prisma + MUSC adjustment is skipped when:

- either file is missing,
- the most recent NSSP week is not present in the data,
- the latest week appears incomplete relative to the prior week,
- or the signal is otherwise too stale to trust.

If the correction cannot be justified, the model falls back to the plain median ensemble without applying the adjustment.

## Notes

- The model is designed around the weekly FluSight update cadence.
- The workflow warns if hub data appear stale relative to the expected due date.
- Plot files should be reviewed before submission.
- All validation checks should pass before a pull request is opened.

This repository is operational code for generating the weekly DMAPRIME-QR_E FluSight forecast, not a generic R package or a setup-only document.
